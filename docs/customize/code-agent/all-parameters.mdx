## 1. CodeAgent Parameters

### 1.1. Core Settings

- `task`: Task description string that defines what the agent should accomplish
- `llm`: Optional LLM instance for code generation. When omitted, CodeAgent tries `ChatBrowserUse` and then `ChatGoogle(model="gemini-2.5-flash")`. Pass `ChatOpenAI`, `ChatAnthropic`, `ChatGoogle`, or another supported chat model to choose explicitly.
- `browser`: Optional `BrowserSession`. Use `browser_session` only for older code; passing both raises `ValueError`.
- `tools`: Optional `Tools` registry. `controller` is a legacy alias; passing both raises `ValueError`.
- `max_steps` (default: `100`): Maximum number of execution steps before termination
- `max_failures` (default: `8`): Maximum consecutive errors before termination
- `max_validations` (default: `0`): Maximum number of times to run the validator agent

### 1.2. Vision and Extraction

- `use_vision` (default: `True`): Include screenshots in LLM messages
- `page_extraction_llm`: Optional separate LLM for page content extraction. A smaller, faster model is enough because it only extracts page text. CodeAgent does not apply a fallback model when this is omitted.

### 1.3. Files and Data

- `file_system`: Optional `FileSystem`. When omitted, every CodeAgent gets a unique temporary directory under the system temp directory. Pass `FileSystem(base_dir=...)` when a stable path is required. Constructing `FileSystem` clears `<base_dir>/openbrowser_agent_data`; keep that subdirectory disposable or use a fresh base directory per run.
- `available_file_paths`: List of file paths the agent can access
- `sensitive_data`: Dictionary of sensitive values to handle carefully

### 1.4. Callbacks and Cost

- `register_new_step_callback`: Optional callback after each execution step. It receives `step_number`, `total_steps`, `code`, `output`, `error`, `thinking`, `screenshot_base64`, and `is_done`.
- `calculate_cost` (default: `False`): Calculate and track API costs

## 2. Run Lifecycle

`code_agent.status` returns a `CodeAgentRunStatus` snapshot. Read it instead of inferring state from logs:

- `phase`: `idle`, `starting`, `running`, `executing`, `validating`, `succeeded`, `failed`, `max_steps`, or `cancelled`
- `terminal`: `true` only for `succeeded`, `failed`, `max_steps`, or `cancelled`
- `success`, `terminal_reason`, `result`, `error`, `attachments`, `step`, `max_steps`, `cancellation_requested`, `closed`, `started_at`, `finished_at`

One CodeAgent instance handles one run. A second `run()` raises `CodeAgentStateError`; create a new instance for another task.

`code_agent.stop()` requests cooperative cancellation between `await` points. A single cell that is already executing is not interrupted. Cancel the `run()` task if that cell must stop immediately. A stop request before `run()` is retained and cancels the next run without starting a browser. A stop request after a terminal phase returns `False`.

A caller cancellation does not prove that the worker stopped. Inspect `status` after cancellation and run any required cleanup before starting another agent.

## 3. Browser Ownership

CodeAgent does not rebuild a caller-provided `BrowserSession` and does not transfer its Python namespace. If the browser fails, inspect `status`, rebuild the browser, and create a new CodeAgent. Namespace transfer with scalar-only preservation applies to MCP context recovery, not to a local CodeAgent run.

`download_file`, `wait_for_download`, `download_outcomes`, `download_failures`, and `list_downloads` are available in the execution namespace. Start `wait_for_download` before the click that triggers a download. A `download_ref` resolves only in the attached session's live download registry; after the session stops or is replaced, read the completed history instead.
