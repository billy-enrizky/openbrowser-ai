## 1. Overview

The MCP server exposes OpenBrowser to Claude Desktop, Claude Code, and other MCP clients. Modern `2026-07-28` clients see seven tools: `create_context`, `execute_code`, `get_status`, `reset_browser`, `close_context`, `web_search`, and `scrape_web`. Call `create_context` before stateful calls. Pass its `context_id` to `execute_code`, `get_status`, and `reset_browser`. Call `close_context` when finished. The stateless `web_search` tool needs no `context_id` and does not start a browser. Its snippets are discovery previews. Scrape and read source pages before you cite them. The stateless `scrape_web` tool fetches one HTTP(S) page in OpenBrowser no-browser mode: it starts no Chrome, Blink, or V8 process and stays on the HTTP path. JavaScript, screenshots, and browser cookies are unavailable on this path. The legacy handshakes `2024-11-05`, `2025-03-26`, `2025-06-18`, and `2025-11-25` see four tools: `execute_code`, `get_status`, `reset_browser`, and `web_search`. Other versions get MCP error `-32602`.

The default stdio transport is a lean JSON-RPC loop. It answers `server/discover` and `tools/list` from a static catalog before it imports the MCP SDK. Set `OPENBROWSER_MCP_TRANSPORT=sdk` to use the MCP SDK 2.3 escape hatch. Invalid values exit with code 2. Both transports share the same context registry and tool implementations. The MCP client supplies the model, so users do not need an external LLM API key.

## 2. Quick Start

### 2.1. Start MCP Server

```bash
uvx openbrowser-ai --mcp
```

The server starts in stdio mode, ready to accept MCP connections. The lean transport is the default. The SDK transport remains available for compatibility checks:

```bash
OPENBROWSER_MCP_TRANSPORT=sdk uvx openbrowser-ai --mcp
```

## 3. Claude Desktop Integration

Add this configuration to your Claude Desktop config file:

### 3.1. macOS
Edit `~/Library/Application Support/Claude/claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "openbrowser": {
      "command": "uvx",
      "args": ["openbrowser-ai", "--mcp"],
      "env": {
        "OPENBROWSER_HEADLESS": "true"
      }
    }
  }
}
```

### 3.2. Windows
Edit `%APPDATA%\Claude\claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "openbrowser": {
      "command": "uvx",
      "args": ["openbrowser-ai", "--mcp"],
      "env": {
        "OPENBROWSER_HEADLESS": "true"
      }
    }
  }
}
```

### 3.3. Claude Code

Add to your project's `.mcp.json`:

```json
{
  "mcpServers": {
    "openbrowser": {
      "command": "uvx",
      "args": ["openbrowser-ai", "--mcp"]
    }
  }
}
```

### 3.4. Environment Variables

Optional configuration:

| Variable | Description | Default |
|----------|-------------|---------|
| `OPENBROWSER_MCP_TRANSPORT` | Stdio implementation: `lean` or `sdk`. Invalid values exit with code 2 | `lean` |
| `OPENBROWSER_HEADLESS` | Run browser without GUI | `true` |
| `OPENBROWSER_RENDER_MODE` | Rendering policy for new contexts: `full`, `lightweight`, or `no-render` | `full` |
| `OPENBROWSER_TEXT_ONLY` | Set to `1` to block external CSS, images, web fonts, media, and text tracks while keeping scripts and screenshots | `false` |
| `OPENBROWSER_BLOCK_RESOURCES` | Comma-separated asset groups to block for new contexts: `css`, `images`, `fonts`, `media`, `scripts` | (none) |
| `OPENBROWSER_ALLOWED_DOMAINS` | Comma-separated domain whitelist | (none) |
| `OPENBROWSER_USER_DATA_DIR` | Optional explicit Chrome profile directory. Omit it for one managed profile per context; concurrent owners are rejected | (auto) |
| `OPENBROWSER_STORAGE_STATE` | Optional JSON file used as a one-time seed for cookies plus localStorage in managed profiles | (auto seed) |
| `OPENBROWSER_COMPACT_DESCRIPTION` | Minimal tool description (~500 tokens vs ~1,430) | `false` |
| `OPENBROWSER_MAX_OUTPUT` | Maximum output characters per execution | `10000` |
| `OPENBROWSER_MCP_START_TIMEOUT` | Browser startup bound in seconds for one execution | `30` |
| `OPENBROWSER_MCP_EXEC_TIMEOUT` | Seconds before a tool call returns a structured timeout result | `110` |
| `OPENBROWSER_MCP_MAX_CONTEXTS` | Maximum open contexts total, including the legacy no-handle context | `16` |
| `OPENBROWSER_MCP_WORKSPACE_DIR` | Base directory for per-context workspaces | `~/Downloads/openbrowser-mcp/workspace` |
| `OPENBROWSER_SHUTDOWN_TIMEOUT` | Browser and context cleanup bound in seconds | `20` |
| `ANONYMIZED_TELEMETRY` | Set to `false` to disable anonymized usage telemetry | `true` |

## 4. Tools

Modern `2026-07-28` clients see seven tools. The legacy handshakes `2024-11-05`, `2025-03-26`, `2025-06-18`, and `2025-11-25` see four tools. Both catalogs include stateless `web_search`.

<Note>
The canonical `web_search` MCP tool name is on the current source branch. The current source server also accepts `search_web` as a call alias. The published `0.1.60` package advertises and accepts `search_web`. Update the installed server or run it from source to see `web_search`.
</Note>

| Tool | Use |
|---|---|
| `create_context` | Create an isolated browser and Python namespace. Returns `context_id` in text and `structuredContent`. Does not start a browser until the first `execute_code` call. |
| `execute_code` | Run Python in one context's persistent namespace with browser automation functions. Modern calls require `context_id`; functions are async unless noted. |
| `get_status` | Read server, context, browser, profile, tab, tools, downloads, storage-state, namespace-transfer, and config lifecycle state as JSON. It does not start or mutate a browser. |
| `reset_browser` | Close a stuck browser and release its profile. Scalar and scalar-only container variables are preserved unless `clear_variables` is true. Inspect `namespace_transfer.dropped`. Cookies and localStorage survive because the profile is reused. |
| `close_context` | Close one context and release its browser and profile. A successful close invalidates the handle. |
| `web_search` | Search without a browser or `context_id` using the package-native DDGS client. The result is JSON text with title, URL, and snippet fields. Snippets are discovery previews. |
| `scrape_web` | Fetch one HTTP(S) URL without a browser or `context_id`. This is OpenBrowser no-browser mode: it starts no Chrome, Blink, or V8 process and stays on the HTTP path. JavaScript, screenshots, and browser cookies are unavailable on this path. It returns JSON with url, title, format, content, stats, and engine_used=http. Use `execute_code` for JavaScript pages. |

If a browser connection fails, call `get_status` before retrying. A page-changing action may have partially run, so do not replay it blindly. `get_status` includes `config.startup`, `config.current`, and `config.restart_required`.

When a profile has been resolved, `get_status` includes `profile.resolution`. Each entry has a `source` key plus a `value`, or a `mode` and optional `count`. The source is `default`, `config`, `environment`, `managed`, or `cli`. Sensitive and unbounded fields expose only a mode and source: `storage_state` is `file`, `memory`, or `none`, `proxy` is `configured` or `none`, and `args` is `configured` or `none` with a count. Cookies, proxy credentials, and argument values are never included.

When a browser session exists, `browser.cdp` reports root transport health. `cdp.healthy` is the last accepted connect or probe observation while the lifecycle preserves an active health claim. An inactive snapshot can report `null` and keeps the history fields. Use `cdp.last_probe_at` to tell whether a probe has run and how recent it is. Use `cdp.healthy`, `cdp.phase`, `cdp.last_probe_at`, and `cdp.last_error_code` before retrying. `cdp.phase` is one of `disconnected`, `resolving`, `connecting`, `connected`, `degraded`, or `failed`. `cdp.last_error_code` is `null` or one of `not_connected`, `timeout`, `connection_closed`, `session_not_found`, `probe_failed`, `connect_failed`, or `cancelled`. `session_not_found` can come from target attachment during connect setup as well as the root probe. `cdp_connected` is only a pointer-presence alias. Root CDP health does not prove a target session, tab, or page can accept commands. MCP probes an existing session before execution when time remains. `get_status` itself is read-only and does not probe or start a browser.

`get_status` adds `browser.health` when a session exists. `health.phase` is `unknown`, `healthy`, `degraded`, `crashed`, `stopped`, or `failed`. The block records page-target crash history, the latest focus-recovery outcome, and a status-time process check. `health.healthy=true` means setup or focus recovery completed. A page read shows the current page state. Hydration and target readiness can differ. Wait while recovery is pending. After a failed recovery, use `reset_browser` only when no usable target exists. `process_present` is `null` when the current CDP root is not bound to the recorded local owner or when process identity is inconclusive, including remote, stopped, and ambiguous local sessions. A missing `health` block means no context has a browser session.

A legacy, invalid, or unreadable config file blocks browser startup and is never rewritten automatically. Execute calls return a `config_*` error with a repair hint. Run `uvx openbrowser-ai config status` to inspect the selected path. Repair the file in place when possible, or move it to a unique backup name before restarting the MCP server. Moving it aside creates a new default and does not migrate old settings. A running MCP server does not hot reload config.

When a browser session exists, `get_status` also includes `browser.navigation`, the active or last navigation transaction. It distinguishes the requested URL from the observed document URL and reports its generation, phase, and error. Navigation waits for the declared document milestone. A `download` outcome is a handoff. The file download continues separately. Milestones track document lifecycle. Application hydration is a separate state.

For a forbidden committed redirect, `browser.navigation.containment` records security cleanup separately. A cancelled or timed-out request may still own a sent cleanup action. An unconfirmed action keeps the old runtime failed. This prevents an unsafe replacement. Read `get_status` before retrying. Status exposes error text for recovery decisions.

For a managed local browser, use `reset_browser` to close the owned browser before replacement. If cleanup fails, the old runtime remains retained. For a remote browser, close the actual browser before creating a replacement `BrowserSession`. Do not assume cancelling a waiter or losing a connection proves that browser execution stopped.

### 4.1. Available Functions

| Category | Functions |
|----------|-----------|
| **Navigation** | `navigate(url, new_tab)`, `go_back()`, `wait(seconds)` |
| **Interaction** | `find_element(role, name, element_id, tag, *, timeout)`, `click_element(...)`, `fill_element(text, ...)`, `click(index)`, `input_text(index, text, clear)`, `scroll(down, pages, index)`, `send_keys(keys)`, `upload_file(index, path)` |
| **Coordinate interaction** | `click_xy(x, y, button, click_count)`, `hover_xy(x, y)`, `scroll_xy(x, y, delta_x, delta_y)` for no-index canvas, PDF, embedded, and native-rendered targets |
| **Dropdowns** | `select_dropdown(index, text)`, `dropdown_options(index)` |
| **Tabs** | `get_tabs()`: list tabs without a DOM scan; `switch(tab_id)`, `close(tab_id)`: accepts the four-character suffix or the full CDP target ID |
| **JavaScript** | `evaluate(code)` -- run JS in page context, returns Python objects |
| **Downloads** | `download_file(url, filename)`; `wait_for_download(timeout, url, lookback, download_ref)`; `download_outcomes()` and `download_failures()` (sync); `list_downloads()` (sync) |
| **Scraping** | `scrape_page(url, format, selector, wait_for, engine)`, `scrape_pages(urls, concurrency, format, engine)` |
| **Web search** | `web_search(query, max_results, backend, region, safe_search, timelimit)`, `web_search_and_scrape(query, max_results, concurrency, format, ...)` |
| **State** | `browser.get_browser_state_summary()` -- page metadata and interactive elements |
| **CSS** | `get_selector_from_index(index)` -- CSS selector for an element |
| **CSS fast paths** | `click_selector(selector, timeout)`, `fill_selector(selector, text)`, `wait_for_selector(selector, timeout)`, `click_selector_and_wait_for_new_tab(selector)` |
| **Completion** | `done(text, success)` -- signal task completion |

Prefer indexed actions whenever an element index exists. Coordinate actions use CSS viewport pixels. If a screenshot uses a `devicePixelRatio` other than 1, divide its coordinates by `window.devicePixelRatio` before calling an `*_xy` function.

**Bundled libraries**: `json`, `csv`, `re`, `datetime`, `asyncio`, `Path`, `requests`, `numpy`, `pandas`. **Only if installed**: `matplotlib`, `BeautifulSoup`, `pypdf` (`openbrowser-ai[pdf]`), `tabulate`.

Variables and state persist between `execute_code` calls within the same context. A context is process-local: it lives until `close_context` or server exit, and a new MCP server process cannot resume the same handle. The browser session inside a context auto-closes after 10 minutes without an `execute_code` call. `get_status` does not refresh that timer. The handle and scalar variables remain, and the next `execute_code` call starts a fresh browser. A successful `close_context` invalidates the handle. If cleanup fails, the result is `close_failed` with `retryable: true`. Retry `close_context` to finish cleanup. The handle cannot be used for `execute_code`, `get_status`, or `reset_browser`. The default limit is 16 open contexts total, including the legacy no-handle context. Set `OPENBROWSER_MCP_MAX_CONTEXTS` to a positive integer to change it. Default workspaces are under `~/Downloads/openbrowser-mcp/workspace/<owner-id>` and default downloads are under `~/Downloads/openbrowser-mcp/<owner-id>`. Each context also has a managed browser profile under `~/.config/openbrowser/profiles/mcp-<owner-id>`. Close retains the profile, workspace, and downloaded files. The owner ID is internal. The `context_id` handle is separate. Read the resolved profile path from `get_status.profile.user_data_dir`. There is no disk quota or expiry cleanup for retained files. `close_context` waits for in-flight calls to finish before it closes the browser and profile. New calls while closing fail with `context_closing`. After a failed close, non-close calls fail with `context_close_failed`. Retry `close_context` only. A second close after success returns `context_not_found`. Server shutdown closes every context and can enter a failed shutdown state if cleanup still fails.

## 5. Example Usage

Once configured with Claude Desktop or Claude Code, you can ask the AI to perform browser automation tasks:

```
"Navigate to example.com and extract all the links"

"Search for 'browser automation' on Google and summarize the first 3 results"

"Go to GitHub, find the openbrowser repository, and tell me about the latest release"
```

The AI will use the `execute_code` tool to write Python code that navigates, interacts, and extracts data.

## 6. Programmatic Usage

You can also connect to the MCP server programmatically:

```python
import asyncio

from mcp import Client, StdioServerParameters

async def use_browser_mcp():
    server_params = StdioServerParameters(
        command="uvx",
        args=["openbrowser-ai", "--mcp"],
    )

    async with Client(server_params) as client:
        created = await client.call_tool("create_context", {})
        context_id = created.structured_content["context_id"]
        try:
            result = await client.call_tool(
                "execute_code",
                {
                    "context_id": context_id,
                    "code": """
await navigate('https://example.com')
state = await browser.get_browser_state_summary()
print(f"Title: {state.title}")
print(f"URL: {state.url}")
""",
                },
            )
            print(result.content[0].text)

            result = await client.call_tool(
                "execute_code",
                {
                    "context_id": context_id,
                    "code": """
links = await evaluate('Array.from(document.querySelectorAll("a")).map(a => ({text: a.textContent, href: a.href}))')
for link in links:
    print(f"{link['text']}: {link['href']}")
""",
                },
            )
            print(result.content[0].text)
        finally:
            await client.call_tool("close_context", {"context_id": context_id})

asyncio.run(use_browser_mcp())
```

Older clients that negotiate `2024-11-05`, `2025-03-26`, `2025-06-18`, or `2025-11-25` keep the original `ClientSession` flow and call `execute_code` without `context_id`.

## 7. CLI Execute Mode

For Bash-based workflows without an MCP client, use the [CLI Daemon](/customize/integrations/cli-daemon) instead. It provides the same `execute_code` functions via `openbrowser-ai -c "code"` with a persistent browser daemon.

The CLI equivalent of `scrape_web` is `openbrowser-ai scrape URL --no-browser`. It starts no Chrome, Blink, or V8 process and stays on the HTTP path. JavaScript, screenshots, and browser cookies are unavailable on this path.

## 8. Troubleshooting

### 8.1. Common Issues

**"MCP SDK is required" Error**

This error can appear only when `OPENBROWSER_MCP_TRANSPORT=sdk` is set. The default lean transport does not import the SDK. MCP is included in the base package since v0.1.30. Update to the latest version:
```bash
pip install --upgrade openbrowser-ai
```

**Browser doesn't start**
- Check that you have Chrome/Chromium installed
- Try setting `OPENBROWSER_HEADLESS=false` to see browser window
- Ensure no other browser instances are using the same profile

**Connection Issues in Claude Desktop**
- Restart Claude Desktop after config changes
- Check the config file syntax is valid JSON
- Verify the file path is correct for your OS

### 8.2. Debug Mode

The MCP server keeps Python logging off the stdio channel so JSON-RPC stays valid. `OPENBROWSER_LOG_LEVEL` is not read by the MCP server. To debug a client integration, inspect the client's captured server stderr or run `uvx openbrowser-ai --mcp` directly in a terminal.

## 9. Security Considerations

- The MCP server has access to your browser and file system
- Only connect trusted MCP clients
- Be cautious with sensitive websites and data
- Use `OPENBROWSER_ALLOWED_DOMAINS` to restrict navigation
